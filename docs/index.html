✨ What is rag-chunk?

rag-chunk is a powerful CLI tool designed for developers building Retrieval-Augmented Generation (RAG) systems. It helps you parse, chunk, and evaluate Markdown documents using multiple sophisticated strategies, ensuring optimal retrieval performance.

🚀 Quick Start

# Install with all features
pip install rag-chunk[all]

# Analyze with semantic chunking and embedding-based retrieval
rag-chunk analyze examples/ \
--strategy semantic \
--use-embeddings \
--test-file questions.json \
--top-k 3

📚 Chunking Strategies

1. Fixed-Size Chunking

Split text into equal-sized chunks by token/word count.

rag-chunk analyze docs/ --strategy fixed-size --chunk-size 200

Best for: Consistent chunk sizes, simple documents

2. Sliding Window

Overlapping chunks to preserve context at boundaries.

rag-chunk analyze docs/ --strategy sliding-window --chunk-size 200 --overlap 50

Best for: Preventing information loss at chunk boundaries

3. Paragraph-Based

Split by natural paragraph boundaries (double newlines).

rag-chunk analyze docs/ --strategy paragraph

Best for: Well-structured documents with clear paragraphs

4. Recursive Character

LangChain's recursive splitter for semantic coherence.

rag-chunk analyze docs/ --strategy recursive-character --chunk-size 200

Best for: Maintaining semantic meaning at split points

5. Header-Aware ⭐ NEW

Split by markdown headers while respecting size limits.

rag-chunk analyze docs/ --strategy header --chunk-size 300

Best for: Technical documentation, structured markdown files

6. Semantic Chunking ⭐ NEW

Use sentence embeddings to split at semantic boundaries.

rag-chunk analyze docs/ --strategy semantic --chunk-size 200

Best for: Maximum retrieval quality, topic-based splitting

🧠 Embedding-Based Retrieval

Traditional lexical matching (keyword overlap) can miss semantically similar content. Enable --use-embeddings to use sentence-transformers for semantic similarity:

# Compare lexical vs semantic retrieval
rag-chunk analyze docs/ --strategy all --test-file questions.json --use-embeddings

🎯 CLI Reference

Option Description Default
--strategy Chunking strategy (or 'all') fixed-size
--chunk-size Tokens/words per chunk 200
--overlap Overlap for sliding window 50
--use-tiktoken Enable token-based chunking False
--use-embeddings Semantic similarity retrieval False
--test-file Path to evaluation JSON None
--top-k Chunks to retrieve per query 3
--output Format (table/json/csv) table

💡 Best Practices

  • Start with header-aware for structured markdown docs
  • Use semantic chunking for optimal retrieval quality
  • Enable --use-embeddings when evaluating with test questions
  • Experiment with chunk sizes: 150-300 tokens for technical docs
  • Use --strategy all to compare all methods at once
  • Add overlap (30-50) for sliding-window to preserve context
